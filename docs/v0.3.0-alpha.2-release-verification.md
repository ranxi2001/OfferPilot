# OfferPilot v0.3.0-alpha.2 发布验证

> 验证日期：2026-08-12（Asia/Shanghai）
> 发布级别：Alpha 补丁；聚焦面试语音播报与回答转写容错。
> 数据处理：不提交真实回答转写、音频、密钥、Prompt、日志或 SQLite 数据库。

## 发布范围

本补丁修复两条语音主链路：面试题使用 MiMo TTS 与官方默认音色
`mimo_default` 播报；回答转写遇到瞬时故障时，由 Go ASR 自动重试，并允许浏览器
复用当前题的同一段内存录音再次分析。Go API 与 Next.js BFF 同时收敛公开错误，
不再把 provider URL、密钥、EOF 或响应正文显示给用户。

本版本没有修改 Agent Harness、面试成功响应、知识 corpus 或 SQLite schema。

## 录音容错契约

| 场景 | 行为 | 用户是否需要重录 |
| --- | --- | --- |
| EOF、UnexpectedEOF、超时、连接重置、broken pipe、GOAWAY | Go 最多尝试 3 次，退避 `100ms / 200ms` | 否 |
| Provider `408`、`429`、`5xx` | Go 最多尝试 3 次；仍失败时保留页面录音并显示“重新分析录音” | 否 |
| 网络或 BFF 到 Go 连接中断 | 返回稳定 `retryable: true`，保留同一 WAV Blob | 否 |
| 不支持的音频格式 | `415`、`retryable: false` | 是 |
| 空转写或无法识别有效语音 | `422`、`retryable: false` | 是 |
| Provider 鉴权或服务配置错误 | `503`、`retryable: false` | 配置修复后再试 |
| 用户取消或切题 | 取消旧请求并淘汰迟到结果 | 不适用 |

缓存绑定面试 ID 和题目 ID，并保留完全相同的 WAV Blob 与原始时长。并发重试只有
最新请求可以提交；重置面试会使迟到的答案结果和执行轨迹失效。开始新录音时，只有
麦克风、AudioContext 和处理节点全部创建成功后才替换旧缓存，因此权限或设备失败
不会销毁仍可重试的录音。

录音只保存在当前页面内存，不写入 `sessionStorage`、IndexedDB 或磁盘。切题、答案
成功提交、生成报告、重置或页面卸载时清除缓存。

## 配置与升级

- 没有新增必填环境变量，也没有依赖图变化。
- 旧 `.env` 若显式设置 `MIMO_TTS_VOICE=alloy`，必须改成
  `MIMO_TTS_VOICE=mimo_default` 并重启 API 与 Web。未设置时自动采用正确默认值。
- SQLite 继续使用 schema v3，没有 migration；升级前仍应按现有部署规范备份敏感
  数据，但本补丁不会重写 schema。

## 回滚与已知边界

- 可直接回滚到不可变的 `v0.3.0-alpha.1` artifact，无需数据库降级。
- 回滚会重新引入旧 TTS 默认音色和转写失败后无法复用录音的问题。
- 页面刷新、关闭、卸载、切题、提交成功或重置后不会保留录音，这是有意的隐私
  边界；旧版本已经释放的录音无法事后恢复。
- 当前会话没有可连接的内置浏览器实例，因此未执行自动点击式 UI 回归；缓存、重试
  标签、迟到结果淘汰和错误语义由单元测试覆盖，真实 HTTP 语音链路已完成冒烟。
