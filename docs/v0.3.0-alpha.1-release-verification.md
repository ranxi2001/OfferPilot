# OfferPilot v0.3.0-alpha.1 发布验证

> 验证日期：2026-08-11（Asia/Shanghai）
> 发布级别：Alpha；用于验证质量基线和故障语义，不代表 v0.3.0 GA。
> 数据处理：只记录版本、命令、计数、阈值和哈希，不提交真实 JD、简历、回答、
> Prompt、密钥、SQLite 数据库、日志或模型私有原始思维链。

## 发布范围

本 Alpha 收敛五项基础能力：逐题知识检索和证据隔离、grounded typed Profile、
Answer 幂等与 SQLite 执行账本、可重复离线 Eval，以及同标签页 snapshot / 安全轨迹
恢复。用户可见轨迹继续只展示安全步骤、状态、耗时和决策摘要。

以下能力不属于本次发布承诺：SSE `Last-Event-ID` 重放、跨进程 durable worker
接管、完整 event-sourced 会话重建、跨设备轨迹同步、真实 provider 的统计质量结论
和 v0.3.0 GA 门禁。

## 候选版自动门禁

最终结果以 `v0.3.0-alpha.1` 标签所指提交的 GitHub Actions 为准。创建标签前运行：

```bash
cd backend
go test ./... -count=1
go vet ./...
go run ./cmd/offerpilot-eval -pretty=false

cd ..
npx tsc --noEmit
npm test -- --run
npm --prefix web run build
npm audit --audit-level=high --registry=https://registry.npmjs.org
npm --prefix web audit --audit-level=high --registry=https://registry.npmjs.org
docker compose config --quiet
git diff --check
```

GitHub CI 还必须完成 API/Web Docker 构建、非 root 用户检查、共享配置卷冒烟和
`/health/ready` 版本断言。本机 Docker 不可用时，不用未执行的本地结果替代该 CI
记录。

Answer 针对性测试已覆盖：

- 相同 `clientAnswerId` 与相同 payload 重放同一个已提交结果；
- 相同 ID 与不同 payload 返回 `409`；
- 已提交问题使用不同 ID 再答返回 `409`；
- 20 个相同并发提交只生成一次 Assessment、turn 和下一题；
- provider 失败不提交 snapshot、command success 或 `answer.committed` 事件，同键可
  重试；
- committed event 写入失败时，snapshot 与 command 在同一事务内整体回滚。

## 数据库迁移

本版本把 `interview_store_migrations` 的最高版本从 1 提升到 3：

| migration | 变更 |
| --- | --- |
| 2 | 新增 command、session event/cursor、model invocation、checkpoint、run lease 和 outbox 表及索引 |
| 3 | 事务内重建 command 表；唯一作用域改为 `(principal_id, session_id, action, idempotency_key)`，subject 唯一键同步加入 principal/action |

Go API 打开数据库时按顺序、逐 migration 事务执行。v1 session snapshot 不被重写；
已有 v2 command 的 ID、hash、状态、结果和错误会保留，并以空 `principal_id` 迁移。

升级步骤：

1. 停止新的面试写流量，并等待进行中的请求结束后停止 Go API。
2. 确认实际 `DB_PATH`；Docker 默认数据库位于 `app-data` volume 的
   `/app/data/offerpilot.db`，文件部署默认是 `data/offerpilot.db`。
3. 创建并验证一致性备份。文件复制时把数据库和存在的 `-wal`、`-shm` 作为一组；
   也可使用 SQLite 在线备份机制。备份包含敏感材料，必须限制访问并加密保存。
4. 部署 Alpha，启动一个 API 实例完成 migration；不要让新旧版本同时写同一文件。
5. 检查启动无 migration 错误、`MAX(interview_store_migrations.version) = 3`，并确认
   `/health/ready` 返回版本 `0.3.0-alpha.1` 后再恢复流量。

本版本没有新增必填环境变量，npm 依赖图没有变化。

## 回滚

migration 是 forward-only，没有自动 down migration。支持的回滚路径是恢复升级前
备份，而不是修改 schema：

1. 停止 Alpha 流量和所有 API 写进程。
2. 保留一份当前 Alpha 数据库用于审计和故障分析。
3. 原子恢复升级前的数据库备份及其必要的 WAL 伴随文件。
4. 部署不可变的 `v0.2.0` artifact，确认 readiness 返回 `0.2.0` 后再切回流量。

恢复旧备份会舍弃升级窗口内创建的会话和答案。不要删除 migration 记录、删除账本表
或手工逆向 command 表；没有升级前备份时，直接让 `v0.2.0` 写入 schema v3 数据库
不属于已验证或支持的回滚方式。

## 已知边界

- 账本表和 persistence API 已具备，但并不等同于完整异步工作流或跨重启自动恢复。
- 当前浏览器主链路仍使用 NDJSON；本 Alpha 不承诺 SSE 游标重放。
- 同标签页刷新依赖公开 SQLite snapshot、事件元数据和有界 `sessionStorage` 安全轨迹；
  不保存答案草稿，因此 provider 失败后再刷新不能自动重放原始答案 payload。
- Profile 的默认生产提取仍是确定性、extractive 路径；模型提取质量的 held-out F1
  门禁尚未完成。
- 知识召回仍是 BM25，没有向量召回、混合检索或 reranker。
- 单机 SQLite snapshot 未加密，且没有账号/tenant 隔离、UI 删除或自动保留策略。
- 可见执行轨迹不会包含模型私有原始思维链；完整体验指完整安全事件，不是泄露私有
  推理文本。
